# Real Data Limitations & Integrity Disclosures: VertiMap Pilot

**Project**: VertiMap — 3D ULPIN Generation & Vertical Property Mapping System  
**Team**: BuzzCodeX (Presidency University) | SIH26011

## 1. Explicit Disclosures & Non-Claims

To maintain total transparency and academic integrity, VertiMap makes the following explicit disclosures:

1. **No Manufacture of Official ULPINs**:
   - Official 14-digit ULPIN codes are generated strictly by authorized land records authorities (Department of Land Resources / NIC / State Revenue Departments).
   - Where a public dataset does not provide an official ULPIN, VertiMap displays the **Source Parcel Survey ID** (e.g. `KA-BLR-SY-42-1`) and clearly marks ULPIN as *"Not available in source dataset"*.
   - The vertical code generated by our system is explicitly designated as a **Proposed VPID** (`<BASE_PARCEL_ID>-<BLDG_ID>-<LVL_ID>-<UNIT_ID>`).

2. **OpenStreetMap is Not Official Cadastral Ground Truth**:
   - Building footprints and `building:levels` tags from OpenStreetMap represent crowd-sourced and remote-sensing derived vector features.
   - While highly accurate for urban spatial representation, they are not legal cadastral boundary determinations.

3. **Subsurface / Basement Data Limitations**:
   - Standard satellite imagery, DEMs, and open street vectors rarely contain underground basement surveys unless explicitly mapped.
   - If an open source dataset lacks verified underground basement geometry for a building, VertiMap displays **"NO VERIFIED SUBSURFACE DATA"** rather than rendering an artificial basement.

4. **Vertical Level Evidence Hierarchy**:
   - When a building has an explicit `building:levels` tag in OSM, its level count is marked as **`OBSERVED (SOURCE ATTRIBUTE)`**.
   - When only building height ($H$) is available or estimated, floor levels are marked as **`ESTIMATED (HEIGHT-DERIVED)`** using a standard storey height ($3.5\text{m}$).
   - If multiple sources disagree (e.g. tagged levels = 4, but height = $21\text{m} \implies 6$ floors), the status is flagged as **`CONFLICTING`** and dispatched to the human review queue.

5. **Validation Test Scenarios vs Real Survey Data**:
   - To demonstrate the system's ability to catch boundary envelope violations and cadastral overhangs during presentations, controlled test cases are provided and explicitly labeled: **"VALIDATION TEST CASE — CONTROLLED QA OVERHANG"**.
   - These test cases are never represented as genuine surveyed infractions.

## 2. Confidence & Uncertainty Quantification Formula

Rather than generating arbitrary percentages, VertiMap computes a deterministic **Evidence Quality Score ($Q$)**:

$$Q = \sum W_i \cdot C_i - \sum P_j$$

### Positive Evidence Weights ($W_i$):
* **Geometry Integrity**: $+30\text{ pts}$ (Valid, non-self-intersecting closed polygon).
* **Direct Parcel Association**: $+25\text{ pts}$ ($100\%$ containment within cadastral parcel boundary) or $+15\text{ pts}$ ($>80\%$ containment).
* **Observed Vertical Attribute**: $+25\text{ pts}$ (Direct `building:levels` attribute from source) or $+15\text{ pts}$ (Height-derived estimate).
* **Terrain Elevation Reference**: $+20\text{ pts}$ (Sampled from 30m SRTM/OpenDEM grid).

### Penalty Deductions ($P_j$):
* **Ambiguous Parcel Association**: $-20\text{ pts}$ (Building straddles multiple cadastral parcels).
* **Missing Vertical Evidence**: $-25\text{ pts}$ (No height or level data available).
* **Conflicting Source Evidence**: $-30\text{ pts}$ (Attribute level mismatch with physical height).
* **Boundary Envelope Violation**: $-35\text{ pts}$ (Structure cantilevers outside parcel envelope).

### Normalized Output:
* **HIGH Confidence**: $Q \ge 80$ (Fully verified geometry and attributes).
* **MEDIUM Confidence**: $50 \le Q < 80$ (Estimated vertical levels or partial containment).
* **LOW / REVIEW REQUIRED**: $Q < 50$ (Conflicting data, boundary overhangs, or missing evidence).
