# Phase 0 — ABSOLUTE RULES

Before changing or generating major application code, obey these rules:

1. Never invent data.
2. Never claim a government dataset exists unless you verify it.
3. Never call synthetic/demo data “official”, “authoritative”, “survey verified”, or “government verified”.
4. Never fabricate model accuracy, confidence, sensor measurements, cadastral ownership, legal rights, or government approvals.
5. Never treat a screenshot as proof of how a system actually works.
6. Inspect source code whenever source is available.
7. Inspect documentation, configuration, tests, data files, deployment files and Git history.
8. Distinguish:
   - VERIFIED FROM CODE
   - VERIFIED FROM EXECUTION
   - CLAIMED IN DOCUMENTATION
   - EXTERNAL SOURCE CONFIRMATION
   - INFERRED
   - UNKNOWN
9. If two files or versions of a project contradict each other, report the contradiction rather than silently choosing one.
10. Never copy another team's branding, UI, source code or proprietary implementation.
11. Extract concepts, algorithms, architecture patterns and lessons, then implement independently.
12. Every major technical claim in the final research report must have a source reference.
